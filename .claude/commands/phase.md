# Phase 워크플로우 진입

Phase 번호: $ARGUMENTS

## 지시사항

1. **Phase 문서 로드**: `docs/phases/phase-{N}-*.md` 파일을 읽어라. `$ARGUMENTS`가 `7`이면 `phase-07-*.md`, `1`이면 `phase-01-*.md`를 찾아라.

2. **Sub-step 목록 파싱**: 문서에서 `### Phase N-M` 패턴의 모든 sub-step을 추출하라.

3. **완료 상태 판정**: 각 sub-step의 "생성할 파일" 목록을 확인하고, 실제 파일 시스템에 존재하는지 검사하여 상태를 판정하라:
   - **DONE**: 생성할 파일이 모두 존재하고 대응하는 테스트 파일도 존재
   - **PARTIAL**: 일부 파일만 존재
   - **TODO**: 파일이 하나도 존재하지 않음

4. **결과 출력**: 아래 형식으로 출력하라:

```
## Phase {N}: {제목}

| Sub-step | 설명 | 상태 |
|----------|------|------|
| Phase N-1 | ... | DONE / PARTIAL / TODO |
| Phase N-2 | ... | DONE / PARTIAL / TODO |
| ...      | ... | ... |
```

5. **다음 작업 안내**: 첫 번째 TODO 또는 PARTIAL 상태인 sub-step에 대해 다음을 표시하라:
   - 생성할 파일 목록
   - TDD 순서 (문서에 있는 경우)
   - 검증 기준 (Phase 문서 하단의 검증 기준 중 해당 sub-step 관련 항목)

6. **특정 sub-step 지정**: `$ARGUMENTS`가 `7-3` 형태이면 Phase 7의 sub-step 3만 상세 표시하라.

7. **사용자 확인 대기**: 출력 후 반드시 **"다음 작업을 시작할까요?"** 라고 물어보고 사용자의 확인을 기다려라. 절대로 자동으로 코드 작성을 시작하지 마라.

## 주의사항

- Phase 번호가 한 자릿수면 앞에 0을 붙여라 (e.g., `1` → `01`)
- 문서가 존재하지 않으면 에러 메시지를 출력하라
- 코드를 작성하지 마라 — 이 커맨드는 조회 전용이다
